  Honest take on each component                                        
                                                                     
  1. Quantitative module — high leverage, cheap.                       
  Indicators are deterministic and validatable. Every signal you add 
  either works on backtest or doesn't, and you can A/B compare.        
  Existing data already supports a lot: foreign-flow z-scores,         
  accumulation streaks, sector rotation, relative-strength. Adding     
  OHLCV (which you have a table for but no data) unlocks the technical 
  layer. This should go first because every later layer benchmarks     
  against quant signals.                                               
                                                                       
  2. News + cron infrastructure — mid leverage, mid cost.              
  Needed if anything downstream depends on news. RSS/Atom from Reuters,
   FT, central banks, DigiTimes is free. Cheap LLM (Haiku 4.5,         
  ~$0.005/article) does extraction + classification. Caveat: news →
  sentiment → trade is a noisy path. Most "sentiment alpha" papers     
  don't replicate.                                                   
                                               
  3. Independent qualitative analysis (narrative-naive Claude) — this  
  is the most interesting idea in your proposal.
  Most LLM analysis is already news-contaminated. If you architect two 
  reasoning paths — one with full news context, one with only          
  structured data + economic frameworks — and then look at where they
  disagree, that disagreement is itself the signal. Where the naive    
  view is bearish but the news-aware view is bullish, you're paying for
   narrative; where they agree, you have conviction. This requires
  strict prompt sandboxing — the naive agent must not see any
  text-derived signal.

  4. ML time-series — low leverage if used for price prediction. Useful
   for regime detection.
  I'd push back on TimesFM/Chronos for predicting tomorrow's close —   
  those benchmarks are macroeconomic series, not equities, and equity  
  day-ahead is dominated by noise. Re-scope it to: volatility regime
  classification, flow anomaly detection, forecast intervals on sector 
  aggregates. That's where these models earn their keep.             
                                               
  5. IB / tycoon view detection — low priority.
  13F filings are 45 days lagged. Bridgewater letters are quarterly and
   hedged. Central bank speeches are the highest-signal piece and      
  already in the news flow. The data is mostly already absorbed by the
  time you read it. Don't build this until phases 1-3 are paying off.

  What the constraints mean

  (read MCP, fetch RSS, classify with Haiku, write a digest). So the question isn't "how do we fit 50 calls into 15 slots"
  — it's "what are the 15 most valuable daily digests we could produce?" That's a much better problem.                     
                                                                      
  Skills for the dual-agent = manual depth-on-demand, not automated. The interesting "narrative-naive vs narrative-aware"  
  reasoning happens when you're about to act on something, not every day on every ticker. That's actually the right shape —
   automating it would have produced expensive noise. The skill design fits the use case: structured MD instructions, run  
  in the Claude app with full project context, output is itself an MD file added to the project.
                                               
  Project files as the source of truth for qualitative output. Neon stores structured/numeric stuff; the project repo (or a
   synced Drive folder) stores text artifacts — digests, theses, journals. Git already gives you versioning + sync; Drive
  is optional.

❯ Discovery candidates What does this do?                                                                                     
  
⏺ The "Discovery candidates" panel surfaces unclassified stocks that are probably AI-supply-chain peers we haven't mapped yet
  — using the market itself to suggest classifications.
     
  How it works
  
  For every grey "context" ticker in the universe, the script:
  
  1. Finds its 5 strongest correlations among the 50 classified tickers
  2. Checks if ≥3 of those 5 share the same pillar (semi / infra / equipment / energy)
  3. Checks if the median correlation to that pillar is ≥ 0.55
  4. If yes → flags it as a candidate, with the suggested pillar and ρ ≈ confidence
  
  The number ρ≈0.68 is the median correlation to the suggested pillar — higher = the unclassified stock is moving in lockstep
  with that pillar.
  
  Why this matters

  It's the same logic a quant analyst uses, automated:

  ▎ "Stock X's stock chart looks identical to TSMC, ASE, and GUC. We don't have it tagged as AI-supply, but it's behaving like
  ▎  one. Worth investigating."
  
  Concretely useful for:
  - Filling gaps in the supply chain — companies that supply AI customers privately, never say so publicly, but their stock
  co-moves
  - Catching reclassification candidates — e.g. an obscure component supplier becomes AI-relevant when a customer ramps
  - Sanity-checking the existing classification — if an unclassified stock has higher conviction (ρ) than some
  currently-classified ones, that's a signal something's off
  
  What you do with a candidate

  If the top candidate looks plausible → use w_add (Telegram or MCP) to drop it on the watchlist with a "discovery candidate,
  needs investigation" reason. Then read the company's 10-K / news to confirm an actual supply-chain link before promoting it
  to dim_supply_chain with a real pillar/node assignment.

  Right now the panel is unreliable because we only have ~40 trading days of data — correlations are noisy in short windows.
  After the full backfill (~2 hours total, currently at 39%), the same query will run on 12 months of data and the candidates
  will be much more trustworthy. The energy/heavy-electrical names are co-moving heavily in the recent rally, which is why
  most current candidates suggest "energy."
  
  In short: it's a cheap automated screen for "what AI-adjacent stocks are we missing?" — useful as a seed for further
  research, not as a final answer.

  ────────────────────────────────────────
  Column: Gain
  Means: ρ at lag − ρ at 0. This is the only column that matters. Positive means upstream genuinely leads; negative means they

  ────────────────────────────────────────
  Column: N obs
  Means: data points in the regression (currently ~38 = ~2 months)
